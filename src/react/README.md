# DedsiArche 前端

独立的 React 管理端基础项目，技术栈参考 DedsiNatives 的 react-admin。依赖版本于 2026-10-28 从 npm 官方仓库核实，使用稳定版。使用 Bun 管理依赖和执行脚本，提交 `bun.lock`。

## 启动

安装 Bun 1.4.2（与 `packageManager` 一致），保留 Node.js 22.13+（22.x）或 24+ 供工具链使用，推荐 Node.js 24 LTS。在仓库根目录执行：

```powershell
cd src/react
bun install --frozen-lockfile
bun run dev
```

访问 http://localhost:11126。进入系统需先登录，登录需要后端服务。

添加依赖使用 `bun add <包名>`，开发依赖使用 `bun add -d <包名>`。手动修改依赖后执行 `bun install` 并提交更新后的 `bun.lock`；CI 使用 `bun install --frozen-lockfile`。不再维护 `package-lock.json`。

需要覆盖默认配置时，将 `.env.example` 复制为 `.env.local`。浏览器直接请求 `http://localhost:11518/dedsi-arche-api`，可通过 `VITE_API_BASE_URL` 修改完整接口地址，不使用 Vite 代理。Axios 客户端位于 `src/services/http.ts`。

## 目录

src/

  services/      HTTP 客户端及后续业务接口
  styles/        全局样式

## 检查与构建

```powershell
bun run lint
bun run typecheck
bun run build
bun run preview
```

提供 development、prototype、test、production 模式，使用 `dev:prototype`、`dev:test`、`dev:prod` 以及对应的 `build:*` 命令。这里的 test 是环境模式，不是自动化测试。按需创建 `.env.[mode]`，所有模式默认使用相同基础配置。

构建产物位于 `dist`。生产服务器需要为前端路由配置回退到 `index.html`。构建时设置 `VITE_API_BASE_URL` 为浏览器可访问的后端完整接口地址，并在后端配置对应 CORS 来源。所有 `VITE_` 变量都会公开给浏览器，不应填写密钥。

TypeScript 沿用参考项目的双版本方案：`@typescript/native` 别名安装 TypeScript 7，使用其 `tsc` 构建；`typescript` 别名安装 TypeScript 6，供尚要求 `<6.1` API 的 typescript-eslint 使用。

保留 `oidc-client-ts` 依赖以对齐参考技术栈，尚未接入身份提供方或登录流程。当前已对接 Java 后端自己的 JWT 用户接口。

## 界面与组件

使用 shadcn/ui（Radix UI）和 Tailwind CSS，组件源码位于 src/components/ui，通过 components.json 管理。使用 bunx --bun shadcn@latest add <组件名> 添加组件。

左侧移除演示菜单，为管理员展示用户管理入口，保留 Logo、底部账户区及折叠功能。首页为账户中心，提供真实个人资料和登录状态管理。旧业务路径统一进入 404。仅面向 PC 端，右侧内容独立滚动，内边距 2rem。

## UI 规范

后续页面统一遵循本节规范，颜色的唯一配置入口为 `src/styles/global.css` 的语义 token。

### 配色

仅使用主题蓝 `#5996FF`、黑色 `#000000`、白色 `#FFFFFF`。中性色通过黑白透明度生成，不添加独立灰色色值、其他彩色、彩色渐变或彩色 emoji。主题蓝可使用透明度表达交互层次。

| 语义 | 颜色 / 透明度 | 使用位置 |
| --- | --- | --- |
| primary | #5996FF | 主按钮、当前导航、选中标签、链接、关键数字 |
| primary-foreground | 白色 100% | 主题蓝背景上的文字 |
| foreground | 黑色 88% | 标题、正文 |
| 次级正文 | 黑色 72% | 次级内容、表头 |
| muted-foreground | 黑色 60% | 辅助说明、日期、非选中导航 |
| 禁用 | 黑色 38% | 仅用于不可用控件，配合 disabled 语义 |
| background / card / popover | 白色 100% | 页面、卡片、浮层 |
| muted | 黑色 2.5% | 表头、弱背景 |
| secondary | 黑色 4% | 统计卡片、分段选择容器 |
| accent | 黑色 6% | 中性悬停背景 |
| border | 黑色 10% | 装饰分割线、卡片边界 |
| input | 黑色 24% | 输入框边界 |
| ring | #5996FF | 键盘焦点轮廓，2px |
| 遮罩 / 阴影 | 黑色透明度 | 遮罩通常 50%，阴影保持轻量 |

不使用红绿橙区分业务状态。成功、取消、待处理等必须同时使用不同的线性图标和明确文字；错误提示使用文字与图标，不能只改颜色。危险操作使用深色按钮与明确操作名称，涉及不可恢复操作时给出确认。语义 token `destructive` 映射为黑色 88%。普通内容不要对整个容器设置 opacity，以免文字和子控件一同变淡；对文字、背景、边框分别指定透明度。

### PC 布局与响应式

- 最小支持视口宽度：1024px。低于该宽度保持桌面布局，允许页面横向滚动，不提供移动导航或手机专用布局。
- 1024–1279px：展开侧栏 200px；1280px 及以上：展开侧栏 240px。
- 侧栏底部展开时左右分为账户信息与折叠按钮两个独立点击区域，中间不加分割线；折叠后隐藏整个账户块，底部仅保留展开图标。折叠／展开按钮仅显示图标，不显示文字。折叠侧栏宽度为 72px，仅显示品牌图标、菜单图标及底部展开图标；图标保留可访问名称与悬停提示。右侧随侧栏宽度调整。
- 右侧内容区域四周内边距统一为 `2rem`，不随 PC 断点改变。
- 左侧栏固定在视口内：顶部品牌、底部用户信息保持可见，中间菜单在高度不足时独立纵向滚动。
- 右侧全部作为内容区域，不设置全局顶部工具栏，高度为视口高度，内容超长时仅右侧出现 Y 轴滚动条，不带动左侧菜单和用户信息。页面标题直接位于内容区顶部。
- 统计卡片固定三列，卡片内部必要时换行。表格保持列结构，宽度不足时只在表格容器内横向滚动。
- 不设置左下角推广、升级卡片。

### 字体、间距与组件

- 字体：Segoe UI / Microsoft YaHei / sans-serif。页面标题 30px、模块标题 16px、正文 14px、表头 13px、辅助信息 12px，数字使用等宽数字。
- 间距按 4px 基准递增；主要内容间距 24–40px，卡片间距 20px，卡片内边距 24px。
- 圆角：小控件 6px、按钮/输入框 8px、卡片 12px；头像与搜索框可使用圆形/胶囊形。
- 普通控件建议 40px 高；表头 64px，数据行 72px。使用轻边框，避免大面积阴影。
- 图标统一使用 Lucide 线性图标，通常 16–20px，不混用彩色图标或 emoji。
- 每页主操作使用主题蓝；普通操作使用白色或黑色透明背景。选中项除颜色外，还应通过底线、背景或字重区分。
- 保留键盘焦点、按钮名称、状态文字、空数据提示。颜色透明度应按实际叠加背景检查对比度，不将禁用级浅色用于正常正文。
- 复用 `src/components/ui` 下的 shadcn/ui 组件；业务页面使用语义类名，禁止新增未经规范定义的颜色。

## 登录页面

访问 `/login` 查看独立登录页。页面使用项目 Logo、主题色与黑白透明度，支持用户名密码、密码显隐、必填校验、加载状态及失败提示。当前后端仅支持用户名登录，不显示第三方登录按钮。登录页不提供创建账户入口或忘记密码提示，账户由管理员在用户管理中新增。

登录调用 `POST /api/users/login`，成功后返回工作空间并展示用户信息。凭据仅保存在当前标签页的 `sessionStorage`，不保存密码；刷新页面可恢复未过期会话。请求自动附加 Bearer 凭据，访问令牌过期后清除本地会话，当前未实现自动续期。退出调用后端 `/api/users/logout` 撤销刷新令牌，成功后清理会话。所有系统页面（包括未知路径）均经过登录守卫。未登录、令牌过期或已认证请求返回 401 时清理会话并跳转登录页；登录成功后返回原站内路径。已登录访问登录页时跳转系统。登录页不提供返回工作空间入口。前端守卫控制页面访问，接口权限仍由后端认证与授权校验。

联调需要启动 Java 后端及其数据库、Redis，浏览器默认直连后端 11518 端口。不能用界面演示替代真实认证。

登录表单只校验必填与纯空白，失焦和提交时给出字段提示，不校验账号密码长度或套用注册规则。用户名提交前去除首尾空白，密码保持原样；提交时禁用表单以避免重复请求。开发及 preview 端口均为 11126。

后端 CORS 默认允许 http://localhost:11126 和 http://127.0.0.1:11126，其他跨域来源拒绝。前端直接请求后端，默认 VITE_API_BASE_URL=http://localhost:11518/dedsi-arche-api。

## 用户功能与真实测试

- `/register` 页面及路由已移除；后端注册接口保持不变。
- `/`：从 GET `/api/users/me` 加载资料，PATCH `/api/users/me` 修改显示名称并同步侧栏；请求失败提供提示，首次加载失败可重试。
- 账户中心的“延长登录”调用 POST `/api/users/refresh`，替换轮换后的两种凭据，同一时刻多个刷新操作合并为一次。当前采用手动续期，到期后重新登录。
- 账户中心和底部账户菜单均可退出。失败时保留会话供重试；成功时撤销刷新凭据并清理本地会话。
- 用户管理支持列表、新增、编辑名称和启停。管理员可重置密码、删除非管理员用户。

运行单元测试：`bun test`。启动真实后端和 PostgreSQL 后运行 `bun run test:e2e:api`，可通过 `E2E_API_URL` 指定后端。该脚本不使用 Mock，执行 26 项断言，覆盖六个用户接口及登录失败、校验失败、重复注册、刷新令牌轮换和退出撤销。每次创建独立 `api_e2e_` 测试用户，保留记录用于核对，不修改既有账户，不打印密码或令牌。

2026-10-29 浏览器端到端验收：未登录访问拦截 → 空注册表单 → 重复注册 → 新账户注册 → 错误密码 → 登录成功 → 查询资料 → 空白显示名称拦截 → 保存显示名称 → 侧栏同步 → 延长登录 → 折叠/展开 → 侧栏退出 → 未登录访问拦截 → 重新登录及页面刷新后资料保留。真实数据库核对测试账号显示名称与会话撤销状态。
## 用户管理

管理员访问 `/users`，支持用户名/显示名称搜索、状态筛选、每页 10 条分页、新增用户、编辑显示名称、启用/停用。保存前校验表单；停用需勾选确认，不能停用本人；并发编辑使用 version 检查，冲突后需刷新重试。列表不返回密码与令牌。

分页查询使用 POST `/api/users/page`，JSON body 包含 keyword、enabled、page、size（默认空关键字、不限状态、第 1 页、每页 10 条）；新增仍使用 POST `/api/users`，编辑仍使用 PATCH `/api/users/{id}`。管理权限由 `USER_ADMIN_USERNAMES`（逗号分隔的已存在用户名）明确配置，默认没有管理员，公开注册不提供授予权限的字段。本机已按用户授权配置 `dedsi_user`。普通用户看不到菜单，直接访问管理页会提示无权限，调用接口返回 403。登录和 /me 返回 canManageUsers，服务端始终重新校验实际权限，不信任前端状态。

停用后后端拒绝该用户的 Bearer 请求，并撤销所有刷新会话。再次启用允许重新登录；原访问 JWT 若尚未到期，也会重新通过启用状态检查，因此启停不是永久撤销访问 JWT 的机制。

真实接口测试：设置 `E2E_ADMIN_USERNAME`、`E2E_ADMIN_PASSWORD` 后执行 `bun run test:e2e:users`。脚本创建独立 manage_e2e_ 账号并验证权限拒绝、查询分页、创建、冲突、停用、启用与会话撤销，不打印凭据。2026-10-29 第一轮通过 24 项断言；另完成真实浏览器新增、分页、编辑、停用确认、状态筛选、普通用户权限、停用后拦截和重新启用登录测试。
### 详情、删除与密码重置（2026-10-29）

操作列提供详情、编辑、重置密码和删除。新增/编辑复用同一个居中 Modal 表单；详情从 GET `/api/users/{id}` 实时读取。弹窗支持键盘焦点约束、Esc/关闭取消、提交中禁止重复操作。

DELETE `/api/users/{id}?version=...` 删除账户及刷新会话。点击行内删除只打开二次确认，点击确认删除才发请求；取消不发送删除请求。当前账户及配置中的管理员不能删除，避免删除后注册同名账号继承管理权限。出现并发版本冲突时提示刷新重试。

POST `/api/users/{id}/reset-password` 接收 password 和 version，新密码按注册密码规则校验。通过独立 credential_version 使旧访问令牌与刷新凭据失效，不因普通资料编辑退出登录；重置本人密码后返回登录页。通过 V2 Flyway 迁移为已有用户/会话添加默认 0 的版本字段，保留既有账号和密码。

真实 API 脚本 `bun run test:e2e:users` 现通过 47 项检查，包含重置后的新旧密码、旧 JWT、旧刷新令牌、删除后不存在与登录失败。仅删除脚本本次创建的测试用户。浏览器真实验收包括 Modal 新增和编辑、详情、密码必填及一致性、旧会话失效、旧密码失败、新密码成功，以及删除取消和确认两个分支。测试中不重置或删除原有用户。
## 全局操作提示

操作成功和请求失败统一调用 `notify.success/error/info`（`src/lib/notify.ts`），由应用根部 `GlobalMessages` 显示顶部居中的浮动提示，不占页面布局。成功/信息提示 3.5 秒、错误提示 5 秒自动关闭，支持手动关闭及悬停暂停，最多同时显示 3 条。使用现有 Radix Toast，沿用主题蓝与黑白配色。字段校验保留在输入框附近，加载与空数据状态仍在内容区显示。
