# 工作流程与交付

1. 先执行根目录 AGENTS.md 的 Trail 检索流程，再读取当前任务所需指南。Trail 不可用、未覆盖或索引失效时按根目录的检索例外处理；大范围代码变更后运行 trail build 更新索引，不手工编造索引。
2. 查看 git status，确认用户已有修改。只改与本次需求相关的文件，避免顺手升级依赖或格式化整个项目。
3. 修改配置、API 或组件契约时同步使用方及对应示例/说明。真实凭据留在已忽略的本地文件中。
4. 默认不运行测试。用户要求“不用测试”时，不运行单元、集成、接口、浏览器或端到端测试，不生成测试账户或修改真实业务数据来验证。
5. 构建只在实现交付或重启需要时执行，不为文档修改额外构建；应明确说明构建与测试的区别。Java 构建跳过测试编译及执行：在 src/java 执行 mvn.cmd package -Dmaven.test.skip=true。不要在此场景运行 mvn verify 或 smoke-test.ps1。
6. 运行方式、配置或服务改动需要生效时按 runtime.md 重启；尊重用户当前停止/暂不启动的要求；只修改文档或提示词不构建、不重启。必要时仅查看启动日志、容器状态和监听端口，不把它们称为端到端验证。
7. Windows PowerShell 脚本含中文时保持 UTF-8 BOM，兼容 Windows PowerShell 5.1。使用绝对路径核对操作目标，尤其是迁移、停止进程和文件删除。
8. 交付用中文简述改动、关键文件、是否重启以及实际执行的构建/测试。明确未测试和未解决问题，不把计划写成完成结果。

常用入口（按任务需要，不是默认都执行）：

| 工作目录 | 命令 | 用途 |
| --- | --- | --- |
| 仓库根目录 | trail map / trail ask "<问题>" --source | 获取代码上下文 |
| src/react | bun install --frozen-lockfile | 安装现有锁定依赖 |
| src/react | bun run dev | 独立启动前端 |
| src/react | bun run build | 生产构建；不等于功能测试 |
| src/aspire | dotnet build DedsiArche.AppHost/DedsiArche.AppHost.csproj | 构建 AppHost，使用本目录 global.json |
| src/java | mvn.cmd package -Dmaven.test.skip=true | 打包后端并跳过测试 |

## “不用测试”的执行边界

- 可以阅读代码、差异和已有日志，检查文档链接、配置结构、进程身份与端口。这些是静态审阅或启动状态检查，交付时如实命名。
- 不自动执行 lint、独立 typecheck、测试脚本或浏览器操作来替代用户测试；必要构建自身包含的编译检查可以执行，并说明结果。
- 执行脚本前先读其实际命令与生命周期钩子，不能仅凭脚本名判断不会测试。run-local.ps1 当前使用 -DskipTests，跳过测试执行但仍编译测试源；-Dmaven.test.skip=true 才同时跳过编译与执行。
- 用户授权迁移时的复制完整性核对与停写属于保留数据所必需的迁移步骤；不借此额外查询业务接口或创建测试数据。
- 用户明确授权测试后，只执行所需范围；共享/真实数据库不得自动创建、删除测试账户或清理数据，除非这些数据操作也已获授权。
