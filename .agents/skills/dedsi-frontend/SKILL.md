# DedsiArche 前端开发

## 工作顺序

1. 遵守 [AGENTS.md](../../../AGENTS.md)，查看工作区状态，先用 Trail 定位当前实现；无命中时说明后精确检索。读取 [前端约定](../../frontend.md) 和 [工作流程](../../workflow.md)。涉及服务启动才读运行指南，涉及 API 修改同时读后端指南。
2. 对照 User 的实际代码与下面的参考文件，不根据旧截图或本 skill 的描述猜测代码。用户明确要求优先；已确认项目规则优先于旧实现。不要把“现有代码如此”当成设计已经正确。
3. 新管理页面读取列表、表单、API 三份参考；只改其中一层则读取相关参考。动手前查阅问题清单，避免复制已知差异。说明本次复用的结构，以及领域字段、状态和操作与 User 的区别。
4. 实现页面、服务、校验、菜单路由及必要说明，保留用户已有改动。一般不另建通用 CRUD 引擎、不新增 UI/状态管理/表单库、不升级依赖。
5. 静态核对契约、状态流与错误场景。根据工作流程进行必要构建；默认不运行测试、lint、独立 typecheck、浏览器或接口验证。只有文档/skill 变更时不构建、不重启。

## 必须保持的实现边界

- 当前用户信息统一在 `services/auth.ts` 加载并随会话存入 `sessionStorage`，复用登录/刷新响应和已缓存的完整 user；缺失资料由 RequireAuth 补取，同一会话的并发 getProfile 请求合并。页面通过 useSession 读取能力，搜索、翻页及刷新列表不得额外请求 `/me`。修改本人资料时更新缓存或主动 refreshProfile，修改其他用户不刷新当前用户资料。退出/过期/401/会话切换隔离旧请求，缓存不能替代后端鉴权。细节见 API 与认证参考。

- 系统编码以纯文本展示，不使用可编辑输入框或清空按钮；新增请求直接使用该次弹窗挂载时生成的 ULID，编辑展示原编码。

- 技术版本以 `src/react/package.json` 和 `bun.lock` 为准，使用 Bun。公共组件来自 `components/ui`；页面只负责界面编排，HTTP 在 `services`，纯业务校验在 `lib`。
- 自定义 `interface` 使用 `I` 前缀，独立接口文件名一致；组件和服务文件不因内嵌接口而改名。`type` 别名不强加 I 前缀；第三方和框架声明合并名称保持原样。
- 新增或修改的业务代码用清晰多行排版；关键字段含义、状态变化、空值转换、并发处理写必要中文注释。不照抄 User 中压成一行的 JSX、接口和事件处理器，也不为未触及文件进行整仓格式化。简单属性不机械逐行注释。
- 管理列表复用 User 的布局和交互；登录、账户中心或用户明确指定的不同页面单独处理。不要将用户专属的密码、本人保护、停用会话规则附加到所有领域。
- 新领域 ID 在前端作为不透明字符串传递；后端除 User 外为 26 位 ULID，不转数字、不自行生成业务 ID。字段、状态、长度和更新语义逐项核对后端，不能机械换名复制 User。
- 系统管理的业务字段 `code` 是上述主键规则之外的已确认场景：每次新增弹窗挂载时通过 `src/react/src/lib/ulid.ts` 生成 26 位全大写 ULID 默认值，重渲染/保存失败不重生成；编辑保留原编码。不要因此改为前端生成实体 id，或自动改变权限编码规则。
- 业务时间直接展示 API 的北京时间本地字符串，不用 Date/toLocaleString 转时区，不加 UTC 兼容。认证过期计时独立使用 `expiresAtEpochMs`。
- 默认仅做 PC 响应式，沿用语义颜色、公共 UI 和现有反馈方式；不要重新设计配色、恢复已删除的装饰内容或公开注册入口。

## 交付前核对

- 页面入口、导航权限、直接访问路由、失效登录、403 展示均有明确行为；前端控制不替代后端授权。
- 筛选提交/重置回到第一页，翻页保留已提交筛选；加载、空数据、失败重试、连续请求、删除最后一条的回退没有遗漏。
- 表格长文本、省略占位、状态中文、时间、操作列、横向滚动和分页完整；没有前端 mock 掩盖接口失败。
- 新增/编辑的字段及 defaultValues、只读/禁用、隐藏字段、校验、错误焦点和提交 payload 一致；确认字段不发送到后端。
- 保存/删除/重置期间阻止重复写入和误关闭；成功后关闭并刷新，失败保留可修正输入；密码关闭后不残留。
- 版本冲突、唯一冲突、404、400、401、403、429、网络失败按业务语义提示，不以 HTTP 409 一概判断编码重复。
- 对照问题清单说明哪些旧问题仍存在；发现新的阻碍或契约冲突及时告知用户，不借创建 skill 擅自修复业务代码。
- 交付分别说明静态审阅、构建、实际执行的测试和是否重启；未验证的行为不能声称通过。
