# 前端约定

新增或修改业务管理页面、表单、API 服务或菜单路由时，读取并应用 [dedsi-frontend skill](skills/dedsi-frontend/SKILL.md)。该 skill 以当前 User 实现为参照，并单独记录旧代码差异；不替代本指南，不把已有问题当作新代码规范。

## 技术与组织

- 当前用户资料统一由 `services/auth.ts` 管理，随会话保存在 `sessionStorage` 的 `dedsi-arche.session.user` 中，登录/刷新返回的完整资料直接复用。缺失资料由 RequireAuth 统一调用 getProfile 补取，同一会话并发请求共享 Promise。管理列表通过 useSession 读取能力，搜索、翻页、刷新列表只请求业务列表，不重复调用 `/me`。修改本人资料后更新缓存，管理员编辑本人后主动 refreshProfile；退出、过期、401 或切换账户时清理旧会话，旧请求不能写回新会话。缓存只控制前端展示，后端各接口仍独立鉴权。

- 业务时间由 API 返回北京时间本地字符串，页面直接格式化文本展示，不通过 Date/toLocaleString 按浏览器时区转换，不兼容旧 UTC 格式。登录 expiresAt 只用于展示，过期计时使用 expiresAtEpochMs 与 Date.now() 比较；缺失新字段的旧会话直接失效。
- 自定义 TypeScript interface 名称统一以 `I` 开头，引用同步更新；独立接口文件名与接口名保持一致。组件和服务文件内的接口不改变所在文件的组件/服务命名。框架声明合并所要求的固定名称（如 `ImportMeta`、`ImportMetaEnv`）及第三方接口保留原名。
- 使用现有 React、TypeScript、Vite、Tailwind CSS 与 shadcn/ui 风格组件；复用 components/ui、services、lib 的实现。
- 使用 Bun 和 bun.lock，不引入 npm/yarn/pnpm 的锁文件。依赖更新需与任务相关。
- 页面负责展示与交互；API 调用放在现有 services 层，沿用统一认证、错误转换与消息提示。
- 前端直接请求后端 API；不在 Vite 中新增代理。API 地址由当前运行模式的配置提供，Aspire 启动时由 AppHost 注入。
- 保留现有路由守卫、权限处理和登录跳转；前端可见性不替代后端授权。

## 已确认的 UI 规范

- 仅做 PC 响应式，不额外设计移动端。
- 主题色 #2563EB；正文 #1E293B、辅助文字 #64748B，工作区 #F3F4F6，表面白色，边框 #E2E8F0；统一使用 global.css 语义变量。
- 左侧菜单深海军蓝 #142238 背景，正文 #F1F5F9、辅助文字 #B0BED0，展开宽度 232px（1024–1279px 为 208px）、折叠 72px；选中项使用实色蓝 #2563EB、白色文字和加粗，支持多层菜单展开/收起。
- 右侧内容独立纵向滚动；page-padding 上下固定 20px，左右固定 24px；内容铺满右侧工作区，不设置最大宽度或居中留白。
- 账户区位于左下角，展开高度约 57px（40px 点击区、上下各 8px 内边距及边框），头像 32px；展开时左侧显示头像和姓名，右侧放纯图标折叠按钮；底部账户触发区不重复展示账号。侧栏折叠后隐藏整个账户块，只保留展开控制。账户弹出菜单的信息展示不受“底部只姓名”限制。
- 页面标题保持简洁，不擅自恢复装饰图标、说明副标题或顶部通栏。
- 搜索区域与数据表格使用两个独立白色面板，各自有细边框与 8px 圆角；搜索面板内边距 16px，标题、搜索面板、表格之间各保持 16px 间距，两侧对齐，不增加二级标题；分页保留在表格面板内部。
- 标题行左侧显示页面名称，右侧放新增按钮；独立搜索面板内筛选条件、搜索和重置靠左排列，不放独立刷新按钮。标题行和表格两端对齐。搜索使用主题色，重置使用描边按钮；重置清空关键词和状态筛选，返回第一页并重新加载列表。
- 控件圆角 4–8px，容器圆角 8–10px；表格使用浅灰表头、隔行弱背景，与分页保持统一白色容器，用户列表表头 44px、数据行 56px，最小表格宽度 1320px；分页区域内边距 1rem。加载、空数据、失败状态清楚可见。

## 交互与表单

- 系统下拉框调用专用 `GET /api/systems/options`，只返回 `code` 和 `name`；不复用分页 API，不循环收集分页完整 DTO。

- 所属系统下拉选项仅展示系统名称，不拼接系统编码；选项 value 与接口参数仍使用系统编码。

- 系统编码直接以纯文本展示，新增和编辑均不能输入或清空；新增请求使用本次弹窗打开时生成的编码。

- 每次打开新增系统弹窗，系统编码默认生成一个 26 位全大写 ULID，使用 Web Crypto 随机数；同一次打开中的重渲染和保存失败不重新生成。编辑保留既有编码。此规则针对系统业务编码，不替代后端生成的实体主键，也不自动扩展到权限编码。

- 权限新增和列表筛选的所属系统使用纯下拉选择，自动加载完整选项，不附加搜索框、查找按钮或分页栏；加载失败保留重试入口。列表默认全部系统，清空选择回到全部，点击搜索后应用；重置同时清空系统筛选。

- 文本输入、文本域、下拉选择、日期和多选的可编辑主体默认使用 `bg-card`，只读/禁用使用 `bg-muted`，由公共组件提供；页面仅在明确特殊场景覆盖，不重复设置白底。不写死白色，不默认透明。复选框、单选和开关保留可识别的选中状态；ghost/link 按钮、菜单项、线型 Tabs 的透明背景属于有意设计，不统一填白。

- 公共 Input 文本类及密码输入、Select 默认支持清空，无需页面逐个接 onClear；清空必须经过现有变更回调以同步受控值和 RHF 状态。只读/禁用控件不显示清空；账户启停等不可留空的业务枚举显式使用 clearable=false。密码显隐与清空图标须预留独立空间。

- 新增或重构表单统一使用 `components/ui/form.tsx` 与 React Hook Form；字段配置负责绑定和校验，复用现有 UI，不混入另一套组件库。接口调用仍放 services。
- Form 内置 input、select、textarea、date、multi-select、radio、switch、checkbox。日期绑定 YYYY-MM-DD 字符串，多选绑定 string[]，开关/复选框绑定 boolean；上传组件暂不实现。复用公共组件的只读、禁用、清空、键盘与焦点行为。
- 字段 rules 支持同步、异步及跨字段校验；整单业务校验放 Form 的 validate，接口错误通过 mapError 映射。校验只能辅助操作，不能替代后端权限和并发检查。
- 用户新增/修改表单使用失焦校验、提交失败后输入重校验；条件字段隐藏时清除值和错误。异步校验与提交期间禁用控件、阻止重复提交和关闭弹窗；关闭后卸载表单以清空密码。
- 新增用户及重置密码复用 PasswordGeneratorInput：生成固定 20 位且包含大小写字母、数字、特殊符号的密码，只赋值密码字段并清空旧确认值；点击复制后由用户手动粘贴确认密码，不自动同步确认值。随机数使用 Web Crypto，密码不记录到日志或持久化存储。
- 组件配置及扩展示例见 `src/react/src/components/ui/form.md`。

- 成功与失败操作反馈使用已有全局提示，不恢复占据页面空间的大块操作结果横幅。
- 必填星号、字段与表单校验错误使用 error 色 #B91C1C，校验失败控件显示红色边框；密码规则说明通过 descriptionTone: error 标红，普通说明仍用辅助文字色。字段校验错误保留在字段附近；常规校验、焦点定位、防重复提交和加载状态应完整。
- 登录账号/密码不额外增加长度校验，仍保留必填等常规校验；不裁剪密码内容。该规则只针对登录，不取消新增用户和重置密码各自现有的长度、字符和确认密码规则。
- 下拉框、弹窗、按钮复用现有组件，不退回浏览器原生下拉框或引入另一套 UI 库。
- 用户管理弹窗仅保留主标题，不显示标题下方说明副标题；字段规则说明保留在字段附近，删除后果放在确认正文。无描述的 DialogContent 显式设置 aria-describedby={undefined}。
- 用户详情以 modal 展示，新增和修改共用表单 modal，删除必须二次确认后才发送请求。
- 保留图标按钮的可访问名称、表单标签、键盘操作与焦点管理；不因视觉上隐藏文字而删除语义。

## 范围与契约

- 每次进入登录页清空当前站点的全部 localStorage 和当前标签页的 sessionStorage，并同步清除内存会话、失效旧用户资料请求。已登录访问登录页也执行清理，不自动跳回系统；登录成功后仍返回经过校验的站内目标路径。清理不能放在每次渲染或表单输入事件中。

- 上述搜索、表格和 modal 规则以现有用户管理页及同类管理列表为基准，不强制套用到登录或其他用途的页面；用户明确的新设计优先。
- 不恢复登录页的公开注册入口、/register 页面、“返回工作空间”链接或已删除的辅助提示。
- API 请求字段、分页基准、错误码与后端保持一致；账号和权限以服务端结果为准，不用前端 mock 掩盖接入失败。
- 整体保持蓝灰配色，表单必填与校验使用上述红色 error token；危险操作的 destructive token 与表单错误色分别管理。
