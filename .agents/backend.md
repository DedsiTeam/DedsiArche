# Java 后端约定

新增或修改 Java 领域、CRUD API、仓储、查询及数据库迁移时，读取并应用 [dedsi-backend skill](skills/dedsi-backend/SKILL.md)。该 skill 负责将本指南落实为对照 User 实现的工作流程，不替代根目录和领域指南的约束。

## 结构

- 字段、record 参数和枚举值旁的简短说明使用普通块注释 `/* 中文说明。 */`；类、接口和方法的文档说明保留 Javadoc `/** ... */`，不要将 record 参数旁的普通说明写成 Javadoc。
- 项目自定义 Java interface 名称统一以 `I` 开头，例如 `IUserQuery`；接口文件名与接口名保持一致，重命名时同步实现类、注入点及其他引用。第三方接口保持原名。
- Java 代码保持清晰的多行排版，不将类、record 字段列表或方法体压缩成单行；长参数列表与查询语句合理换行。领域字段、请求/响应字段、类与关键方法补充中文注释，说明业务含义、约束与职责。
- 保持 Spring Boot 多模块结构：Host 负责启动和装配，common 放共享基础类型，system 放当前业务。
- 领域按 api / domain / infrastructure 组织。沿用项目现有 API 编排方式，不擅自增加 Application、DO、ApiMapper 等层级。
- 通过 Trail 查找同类实现后扩展，不另建平行的认证、异常处理或数据访问体系。
- 模板相关改动同时考虑生成项目路径；公共脚本位于 src/scripts，生成项目仍可能使用自己的 scripts。

## 接口与认证

- 保持现有 DTO、异常响应、HTTP 状态与分页语义；修改 API 时同步前端调用和相关说明。
- 用户分页查询使用 POST 和 JSON body；不要因此把其他接口一并改成 POST。
- 管理用户的服务端操作必须校验管理员权限；保留当前账户保护、乐观锁/版本冲突和会话撤销等现有行为。
- 保留明确来源的 CORS 白名单，不为解决联调问题改为通配符或关闭鉴权。
- 不在日志、错误响应或 DTO 中暴露密码、密码摘要、JWT 密钥或刷新令牌。
- 未经用户要求，不恢复公开注册页面、默认管理员密码或自动创建管理员。

## 数据

- 除 User 保留 UUID 主键外，其他领域主键必须使用 26 位 ULID 字符串（Java String、数据库 varchar(26)）；关联字段须与被引用主键保持相同类型和格式。
- 业务时间统一北京时间 Asia/Shanghai：Java 使用 LocalDateTime，显式按该时区获取当前时间；数据库使用 timestamp without time zone，API 输出无 Z、无时区偏移的 ISO 本地时间。禁止新增 UTC 兼容分支和前端时区转换。JWT 的 NumericDate 与认证计时用数值时间戳遵循协议，仅限认证边界，不用作业务时间展示。
- 保留现有 JPA、仓储和查询职责划分；数据库结构通过 Flyway 迁移。
- 新建表、增加字段或变更字段含义时，在迁移中同步维护中文 `COMMENT ON TABLE` / `COMMENT ON COLUMN`，覆盖每个业务字段。说明业务含义，并按需标明时间口径、状态取值、单位、关联关系及默认值；不能只用 SQL 行注释或 Java 注释代替数据库注释。已执行迁移缺失注释时新增迁移补充，不改历史文件。
- 已执行的迁移不要改写，后续结构变更新增迁移；不把 Hibernate 配置改成 create/create-drop 来绕过问题。
- 按领域维护完整 SQL 结构快照，位置为 `src/java/docs/sql/system/`：用户及刷新会话归入 `users.sql`，权限归入 `permissions.sql`，系统管理归入 `managed_systems.sql`。快照包含最终字段、约束、索引和中文注释；结构变更时随迁移同步更新并注明对应版本。快照仅供阅读参考，不进入 Flyway 扫描目录、不代替迁移，也不直接执行到已有业务库。
- 运维数据迁移、直接删库/清表必须按用户授权范围操作，确认来源、目标及可恢复副本；业务用户删除继续遵循接口鉴权和 UI 二次确认，不要求每次业务删除额外执行数据库备份。
- 随机密码应在明确初始化/轮换时生成并持久保存，不在每次启动时重新生成。
- 已存在 PostgreSQL 数据时，改配置密码不会修改数据库角色密码。轮换需同步数据库与授权范围内的连接配置，不能靠重建数据库解决。

## 修改范围

- 新增或修改领域行为时补充所属业务模块的纯单元测试，按后端 skill 覆盖业务规则和边界，不加载 Spring 或外部依赖。是否执行仍遵守用户授权及默认不运行测试的约定；测试、集成测试和构建结果分别说明。
- “不校验登录账号/密码长度”只适用于登录场景，不能删除创建用户或密码重置的现有校验。
- 修改公共安全或用户状态逻辑时检查登录、刷新、停用、删除、重置密码的相关调用方，保留已有会话失效语义；没有测试授权时进行代码审阅，不实际调用这些接口验证。
- 新接口和行为变更应更新已有文档/示例，不复制另一套互相漂移的 API 契约。
